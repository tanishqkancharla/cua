## `opensky-driver skills`

Install, update, inspect, or remove the optional agent skill pack.

The install script never touches agent skill directories automatically.

```text output
opensky-driver skills [COMMAND]
```

Without a subcommand, runs `opensky-driver skills status`.

**Examples**

```bash test="cli-shape" id="ref-opensky-driver-skills"
# Report skill-pack state
opensky-driver skills
```

## `opensky-driver extension`

Inspect and manage signed, target-specific optional extensions.

Verified installs bind a pinned publisher identity and Ed25519 key validity/rotation state to exact catalog, archive, manifest, file, original-model, and converted-model hashes plus component licenses/notices and corresponding-source revisions. Inspect previews license, source, and provenance before mutation. Explicit developer-only unsigned installs remain visibly unverified. Install, update, and remove use platform-specific ownership and link/reparse-point checks on macOS, Linux, and Windows.

```text output
opensky-driver extension [COMMAND]
```

Without a subcommand, runs `opensky-driver extension list`.

**Examples**

```bash test="cli-shape" id="ref-opensky-driver-extension"
# List known extensions
opensky-driver extension list
```

## `opensky-driver perception`

Parse a local PNG with the installed optional perception extension.

This read-only local-input mode does not create a Driver capture. Its visual-regions JSON marks the result ineligible for Driver action authority.

```text output
opensky-driver perception <COMMAND>
```

**Examples**

```bash test="cli-shape" id="ref-opensky-driver-perception"
# Parse a PNG into visual regions
opensky-driver perception parse --image screen.png --capture capture.json --json
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure: the daemon is not running or is incompatible, a tool call returned an error, or the operation failed. `call` and direct tool invocations exit with the daemon's result code (1 on a tool error); `update --apply` passes through the installer's status. |
| `2` | Invalid input: tool arguments that are not valid JSON, an unknown `mcp-config` client, or an `update --apply` refused on a local development install. |
| `64` | Usage error: an unknown or missing subcommand or argument, or conflicting flags (for example `revoke` without exactly one of `--session` or `--all`, or an authorization flag passed to `mcp`). |
