`opensky-driver permissions status` reports the selected daemon's native platform prerequisites: X11/AT-SPI on Linux, integrity/UIA on Windows, and attributed TCC grants on macOS. It is not proof that a target application action or capture will succeed.

- `permissions status --socket <path>` reads only that endpoint. An absent endpoint reports `status: "unknown"` and `daemon_running: false`; it never falls back to the default daemon. The command is read-only and never prompts. On macOS it does not run the ScreenCaptureKit probe (macOS Tahoe can show a separate dialog for it), so it reports `screen_recording_capturable: null` and `direct_capture_status: "not_checked"`, plus the last successful `permissions grant` verification when one is recorded for the running driver identity.
- `permissions grant` launches the installed `OpenSkyDriver.app` through LaunchServices so the prompts attribute to the app, then requires a successful live capture probe. It refuses `--socket` with exit64 before any grant UI. It never sends a prompt-capable request over the daemon socket.
- Embedded hosts, in-process `CuaDriver.create()` runtimes and `cua-driver mcp --direct` own their own prompts: there, `check_permissions` stays read-only even with `{"prompt": true}`.
- After a grant changes, quit and relaunch the responsible app (`OpenSkyDriver.app`, or the host of a direct runtime).

See [Permissions](/cua-driver/guides/permissions) for the grant flow and recovery.

Every command also accepts the [global options](/cua-driver/reference/cli#global-options).

## `opensky-driver permissions`

Read native platform status or raise installed-app macOS TCC grants.

Status reports the selected daemon: Linux X11/AT-SPI, Windows integrity/UIA, or macOS TCC. Grant configures the installed macOS app and refuses --socket.

```text output
opensky-driver permissions [COMMAND]
```

Without a subcommand, runs `opensky-driver permissions status`.

**Examples**

```bash test="cli-shape" id="ref-opensky-driver-permissions"
# Report native platform status
opensky-driver permissions
```

### `opensky-driver permissions status`

Report native platform status through the selected running daemon (read-only, no prompt). The default subcommand.

An unavailable selected endpoint reports unknown without falling back to another daemon.

```text output
opensky-driver permissions status [OPTIONS]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="opensky-driver-permissions-status--socket"></span>`--socket` | string |  | Override the exact daemon socket or named-pipe path. |
| <span id="opensky-driver-permissions-status--json"></span>`--json` | boolean | `false` | Emit machine-readable output. |

### `opensky-driver permissions grant`

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure: the daemon is not running or is incompatible, a tool call returned an error, or the operation failed. `call` and direct tool invocations exit with the daemon's result code (1 on a tool error); `update --apply` passes through the installer's status. |
| `2` | Invalid input: tool arguments that are not valid JSON, an unknown `mcp-config` client, or an `update --apply` refused on a local development install. |
| `64` | Usage error: an unknown or missing subcommand or argument, or conflicting flags (for example `revoke` without exactly one of `--session` or `--all`, or an authorization flag passed to `mcp`). |
