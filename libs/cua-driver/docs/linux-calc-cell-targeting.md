# Preserve the selected Calc cell across consecutive edits

OpenSky's frozen Linux release evaluation fills the requested blanks but also overwrites four existing student names. A real public-SDK regression using the original OSWorld workbook reproduces the problem in two edits: click C10, type, Enter, click the retained C11 index, type, Enter, save. C10 is written, C11 remains blank, and C12 is overwritten. A visible-name-box control changes only C10/C11. Both owned app groups and containers exit.

Screenshots isolate the error to the second click: C11 is selected after the first Enter, then C12 is selected before the second typing action. The requested cell's AT-SPI identity and TableCell Position remain unchanged. Its reported Screen coordinates change after editing while Window coordinates remain unchanged; the current X11 rebase then adds another offset. Parent-table point lookup shares the initial stale coordinate system, so it cannot independently validate physical targeting. A blanket offset removal or hardcoded tolerance would not be justified.

Scope: investigate a native X11 single-cell selection route for an unmodified single indexed click through the owning table's advertised Selection interface. Preserve exact window/token/cell identity, modifiers and multi-click semantics, and never replay after uncertain mutation. No product change is yet validated. Issues are disabled in this fork; the linked draft PR serves as the problem record.

Acceptance requires the unchanged public-SDK regression and name-box control to save only C10/C11 with all other values and sheet order unchanged. Check existing selections, keyboard focus, and multi-selection behavior rather than trusting a successful SelectChild acknowledgment. Retain initial failures. Run affected canonical Linux certification on the stable candidate, existing indexed-click and focus regressions, and displaced Code/font controls; do not alter the frozen paid campaign or claim macOS/Windows/Wayland verification from X11 evidence.
